# Практическая работа №2 — веб-приложение для развёртывания за реверс-прокси

Минимальное веб-приложение на чистом Python (стандартная библиотека,
`http.server`, без Flask/FastAPI и сторонних зависимостей), которое
можно запускать несколькими идентичными экземплярами и балансировать
между ними в лабораторной работе №3.

## Запуск

```bash
python app.py
```

Переменные окружения: `PORT` (по умолчанию `8080`), `NODE_ID`
(по умолчанию — hostname процесса).

## Эндпоинты

- `GET /` — HTML-страница с указанием ноды, ответившей на запрос.
- `GET /api/info` — та же информация в JSON.
- `GET /healthz`, `GET /readyz` — проверки живости/готовности.

Каждый ответ также содержит заголовки `X-Node-Id` и `X-Hostname`.

## Соответствие ограничениям практической работы

1. **Идентификация backend-узла.** `/`, `/api/info` и заголовки
   `X-Node-Id`/`X-Hostname` во всех ответах явно показывают, какая
   нода обработала запрос.

2. **Отказоустойчивое хранилище.** Приложение не использует БД или
   любое внешнее хранилище — состояние не хранится, поэтому сценарий
   "нода хранилища недоступна" неприменим по дизайну.

3. **Без TLS/SSL в приложении.** Сервер работает только по обычному
   HTTP — терминация TLS предполагается на уровне Apache/Nginx в
   следующей работе.

4. **Без пользовательских сессий.** Логин, корзины, cookie и т.п. не
   реализуются и нигде не хранятся.

## Потребление ресурсов

Один инстанс на чистом `http.server` потребляет порядка 15–25 МБ RSS
и запускается почти мгновенно.
